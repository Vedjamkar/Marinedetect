# Demo Briefing

Everything needed to present this without fumbling: the stack, what actually happens when
you click Run, and answers to the questions that will come.

Read this once before presenting. It assumes no prior familiarity with the code.

---

## 1. What the system does, in one breath

It finds objects in side-scan sonar imagery and works out **how tall they stand off the
seabed**, by measuring the length of the acoustic shadow behind them.

It deliberately does **not** report water depth or position. Those come from a bathymetric
survey and from GPS/INS — not from an image. The interface says so on screen rather than
filling the field with a plausible number.

That distinction is the whole point of the project. If you remember one sentence, make it:

> *"The neural networks do perception. The geometry does measurement. Depth and position come
> from instruments we don't have on this bench, so we don't report them."*

## 2. Tech stack

### Backend

| Component | Choice | Why |
|---|---|---|
| Language | Python 3.11 | Ecosystem for the model tooling |
| API | FastAPI + Uvicorn | Typed request/response models, automatic validation |
| Schemas | Pydantic v2 | The honesty rules are enforced in the type system, not by convention |
| Detection | Ultralytics YOLOv8n | Small enough to train on a 4 GB GPU |
| Segmentation | PyTorch U-Net, 3 classes | Written in-repo (`backend/ml/unet_arch.py`), not a library model |
| Imaging | OpenCV, NumPy, Pillow | Profile extraction, ROI cropping, annotation rendering |
| Plots | Matplotlib (Agg) | Server-side profile figures |
| Tests | pytest — **63, all hermetic** | Pass with or without model weights on disk |

### Frontend

Deliberately **no framework**. One HTML file, ~1,000 lines, vanilla JS, no build step, no
`node_modules`, no bundler. It is served as a static file by the same FastAPI process.

Reason: it has to run on an unknown laptop, offline, with nothing installed beyond Python.
A React build would add a toolchain that can fail on the day and buys nothing here.

| Concern | Approach |
|---|---|
| Charts | Inline SVG generated in JS from the API's returned array — no charting library |
| Fonts | Spectral, Fira Sans Condensed, Fira Mono — **served locally from `/fonts/`** |
| Layout | CSS grid + custom properties |
| Interaction | Pointer events with pointer capture for the geometry simulator |

**The fonts are bundled on purpose.** They were loading from Google, which meant a venue with
no wifi would have dropped the typography to Times New Roman mid-presentation. There are now
zero external network requests — verified. The demo runs fully offline.

### Machine learning, honestly stated

| Model | Trained on | Result |
|---|---|---|
| `best.pt` (default) | SCTD, 286 train / 71 val | mAP@0.5 **0.794** |
| `debris_crabpot.pt` | crab-pot set, 5,721 train / 555 val | mAP@0.5 **0.465** — partial run, stopped at epoch 12/25 |
| `unet.pth` | 269 weakly-labelled ROI crops | foreground IoU **0.273** (highlight 0.328, shadow 0.196) |

Every one of these is a real measured number on a held-out split. None is quoted from a best
epoch. **The U-Net labels are weak** — generated by thresholding, not human annotation — and
should always be described that way.

## 3. What actually happens when you click "Run inference"

Worth knowing, because someone will ask you to walk through it.

```
Browser                     FastAPI                          Models
   |                           |                                |
   |-- POST /api/v1/inference->|                                |
   |   image + geometry JSON   |                                |
   |                           |-- validate size while streaming to disk
   |                           |-- load image, normalize 16-bit if needed
   |                           |                                |
   |                           |-- yolo_service.predict() ------>| YOLOv8
   |                           |   (converts RGB -> BGR first)  |<- boxes
   |                           |                                |
   |                           |-- for each detection:          |
   |                           |     crop padded ROI            |
   |                           |     measure_shadow()  <- classical, no model
   |                           |     unet_service.segment() ---->| U-Net
   |                           |                                |<- class map
   |                           |     measure_shadow_from_mask()  |
   |                           |     cross_check_shadows()       |
   |                           |     compute_height()            |
   |                           |                                |
   |                           |-- render annotated image + panels
   |<-- JSON + image URLs -----|                                |
   |                           |                                |
   |-- draws the chain, profile SVG, segmentation panel
```

**Where each file lives**

| Step | File |
|---|---|
| Endpoint, orchestration, timings | `backend/api/inference.py` |
| Detector (load-once, COCO guard) | `backend/services/yolo_service.py` |
| **Shadow measurement + height** | `backend/services/shadow_service.py` |
| Binds detection to masks, cross-check | `backend/services/fusion_service.py` |
| U-Net loader (shape-validating) | `backend/services/unet_service.py` |
| Annotation + segmentation panels | `backend/utils/visualization.py` |
| Response shape, honesty rules | `backend/schemas/responses.py` |
| The whole interface | `backend/static/index.html` |

`shadow_service.py` is the file to open if anyone asks to see code. It contains the
measurement and the physics, and it depends on no model at all.

## 4. The physics, in the order you would explain it

```
slant range     R  = sound_speed x travel_time / 2
ground range    G  = sqrt(R^2 - H^2)
object height   h  = H x Ls / (G + Ls)
```

`H` is the towfish's height above the seabed, measured by its own altimeter. `Ls` is the
shadow length, measured from the image.

**Two things people get wrong, so say them first:**

1. **`H` is an input, not an unknown.** Solving the second equation for `H` gives a number
   that is not the target's depth. The equation yields ground range.
2. **Height is barely affected by sound-speed error.** `Ls` and `G` scale together, so a 3%
   error in assumed sound speed moves the height by about 0.2%. Range estimates carry that
   3%; height does not.

Assumption to state, unprompted: **a locally flat seabed.** On a slope the shadow stretches
or shortens and the estimate carries that error.

## 5. Running the demo — the sequence

1. **Start it.** `python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000`,
   then open `http://127.0.0.1:8000/`. Do this before you are on stage; the first model load
   is warmed at startup so the first click is fast.

2. **Click the "verify" tile** (first in the gallery). Geometry auto-fills. Click
   **Run inference**.

   You get:

   ```
   true height    1.60 m
   recovered      1.61 m
   error          0.4%
   ```

   **This is the strongest thirty seconds you have.** Say: *"That is a synthetic target with
   a shadow generated from a known height. The pipeline was never told the answer — it
   measured the shadow and inverted the geometry."*

3. **Click a "ship" tile** to show a real wreck. Walk the chain top to bottom:
   detection → segmentation → shadow → height → what we do not claim.

4. **Scroll to the geometry simulator.** Drag the towfish up and the shadow shortens. Hand
   the mouse to a judge. This is the moment the relationship becomes obvious rather than
   asserted.

5. **Debris:** nothing to switch. Both detectors run on every frame, and each detection is
   labelled with the model that found it. Click a *crab pot* tile to show debris; click a
   *ship* tile to show a wreck. Same session, no restart.

## 6. Questions you will get

**"How do you get depth from a 2D image?"**
You don't, and you shouldn't. Depth comes from bathymetry or an echosounder. What sonar gives
is horizontal position and — uniquely — object height from shadow geometry. Point at the
"what we do not claim" panel.

**"Why is the accuracy low?"**
Which model. The seabed-object detector is mAP@0.5 0.794. The debris detector is 0.465,
because crab pots are *small* — median box 44 px against 271 px for wrecks, and a third of
them are "small" by COCO's definition. The gap between mAP@0.5 and mAP@0.5:0.95 shows they
are found but poorly localized. The fix is a higher-resolution detection head, which was
training when we packaged this.

**"Is the U-Net any good?"**
Not yet. Foreground IoU 0.273, trained on 269 weakly-labelled crops where the labels came
from thresholding rather than a person. That's why the classical profile method drives the
height and the U-Net only cross-checks it. When the U-Net's shadow IoU beats the profile
method, that ordering changes — it's set by measurement, not preference.

**"Why do two shadow measurements disagree?"**
Because they're independent, and showing that is the point. Averaging them would hide the
disagreement, which is the useful signal. Divergence flags a detection for review instead of
reporting it with false confidence.

**"What's it trained on? Is it Indian data?"**
No. SCTD (open sonar dataset) and an open crab-pot survey from Delaware. Indian coastal
survey data is the obvious next step and needs a data-sharing arrangement with a hydrographic
authority.

**"Can it run in real time on a boat?"**
Not as it stands. It's shore-side batch processing of recorded survey lines. Inference is
~90 ms per frame on a GPU, ~600 ms on CPU, but the deployment story is analyst review, not
autonomous dispatch.

## 7. Do not claim

- Any accuracy figure not in the table in section 2.
- That it detects marine debris **when the default detector is loaded** — that one is
  ship / aircraft / human.
- Depth, latitude, longitude, or 3D reconstruction.
- That the U-Net is trained on human annotations. It is not.

If you don't know an answer, say the system reports what it can measure and names what it
can't — and that's checkable on screen. That answer is always available and always true.

## 8. If something breaks on stage

| Symptom | Do this |
|---|---|
| Port 8000 busy | Restart with `--port 8001`, open that instead |
| No detections on a sample | Expected on some frames. Say so and click another — it is not a crash |
| Server won't start | `python scripts/setup.py --check` prints exactly what is missing |
| Everything failed | The physics still stands on its own. Open `shadow_service.py` and walk the formulas; the verification test proves the chain independently of any model |

The service is designed to degrade rather than crash: with no weights at all the API still
answers, and the shadow measurement and height calculation still work, because they use no
neural network.
